범주화(일반화)는 값을 **덜 자세하게** 바꾸는 기법입니다. 나이를 연령대로, 상세 주소를 시·군·구로 바꾸면 분석에 필요한 경향은 유지하면서 특정 개인을 알아보기는 어려워집니다. 실무에서 가장 많이 쓰는 기법입니다.

## 요약

- **범주화**: 값을 구간이나 상위 분류로 바꿉니다. (37세 → 30대)
- **라운딩**: 숫자를 정해진 단위로 반올림·올림·내림합니다. (4,270만 원 → 4,000만 원대)
- **상·하단 코딩**: 너무 크거나 작은 값을 경계값으로 묶습니다. (90세 이상 → "90세 이상")

## 기법별 예시

| 기법 | 원본 (가상) | 처리 후 | 쓰임 |
|---|---|---|---|
| 범주화 | 37세 | 30대 | 연령·소득 구간 분석 |
| 문자 데이터 범주화 | "강남구 역삼동" | "강남구" 또는 "서울 동남권" | 지역 분석 |
| 일반 라운딩 | 152,000원 | 150,000원 | 금액 분석 |
| 랜덤 라운딩 | 152,000원 | 150,000원 또는 160,000원 (무작위) | 역산을 어렵게 |
| 상단 코딩 | 연소득 12억 원 | "5억 원 이상" | 극단값 보호 |
| 하단 코딩 | 거주 기간 0.2년 | "1년 미만" | 극단값 보호 |
| 로컬 일반화 | 튀는 레코드의 값만 더 넓게 | 해당 사람만 "50대 이상" | 정보 손실 최소화 |
| 날짜 범주화 | 2026-03-17 | 2026-03 또는 2026년 1분기 | 날짜 조합 위험 감소 |

## 예제: 범주화로 재식별 위험 낮추기

`code/02_k_anonymity.py`에서 생년·성별·우편번호·직업을 그대로 두면, 7명 모두 조합이 달라 **모두 혼자**입니다. 범주화만 해도 위험이 크게 줄어듭니다.

```text
[처리 전] 준식별자(생년·성별·우편번호·직업)  k=1, l=1, 혼자인 사람 7명
[범주화 후] 준식별자(연령대·지역·직업)        k=1, l=1, 혼자인 사람 1명
```

생년 → 연령대, 우편번호 5자리 → 앞 3자리로 범주화하고 성별을 준식별자에서 뺐더니, 혼자인 사람이 7명에서 1명으로 줄었습니다. 남은 1명은 04-1의 행 삭제나 로컬 일반화로 처리합니다.

[[TIP("요령: 구간 폭은 분석 목적에 맞춰")]]

"10세 단위"가 늘 정답은 아닙니다. 청소년 분석이라면 "13~15세, 16~18세"가 필요할 수 있고, 은퇴 분석이라면 "60~64세, 65세 이상"이 의미 있습니다. **분석 목적에서 필요한 최소한의 세밀함**을 정하고, 그다음에 위험을 확인하세요.

[[/TIP]]

## 주의할 점

- **조합 위험**: 각 항목을 범주화해도, 여러 항목을 조합하면 다시 특정될 수 있습니다. 반드시 조합 기준으로 확인합니다. (04-6)
- **경계값 역산**: 일반 라운딩은 원래 값의 범위를 짐작할 수 있습니다. 민감한 수치는 랜덤 라운딩을 고려합니다.
- **통계 공표**: 범주화한 결과를 표로 공표할 때 칸 하나에 1~2명만 있는 경우는 숨기거나 합칩니다.
