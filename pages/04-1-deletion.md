삭제는 가장 단순하고 확실한 가명처리 기법입니다. **분석에 필요 없는 식별 정보는 처음부터 지우는 것**이 모든 가명처리의 출발점입니다. 이 페이지에서는 삭제의 종류와 언제 무엇을 지울지 판단하는 방법을 다룹니다.

## 요약

- **항목 삭제**: 이름·연락처처럼 분석에 필요 없는 식별자 열을 통째로 지웁니다.
- **부분 삭제**: 주소의 상세 부분, 번호의 일부처럼 값의 일부만 지웁니다.
- **행(레코드) 삭제·로컬 삭제**: 너무 튀어서 특정될 위험이 있는 일부 레코드나 값만 지웁니다.

## 삭제의 종류

| 기법 | 설명 | 예시 (가상) |
|---|---|---|
| 항목 삭제 | 열 전체를 삭제 | 이름 열 삭제 |
| 부분 삭제 | 값의 일부를 삭제 | 서울시 강남구 역삼동 123-4 → 서울시 강남구 |
| 행 항목 삭제 | 특정될 위험이 큰 레코드 전체를 제외 | 1명뿐인 "60대·134 지역·의사" 레코드 제외 |
| 로컬 삭제 | 특정 레코드의 특정 값만 삭제 | 그 사람의 "직업" 값만 비움 |
| 통계 처리(총계·부분총계) | 개별 값 대신 합계·평균으로 바꿈 | 개인 연봉 → 부서 평균 연봉 |

## 예제: 삭제와 함께 쓰는 처리

저장소의 `code/01_techniques.py`는 가상 고객 7명의 데이터에 여러 기법을 함께 적용합니다. 그중 삭제에 해당하는 부분은 다음과 같습니다.

```text
[원본] {'이름': '김민수', '휴대폰': '010-2345-6789', '생년월일': '1983-04-12', '우편번호': '06236', ...}
[처리] 이름·휴대폰 열 삭제 → 휴대폰은 키 기반 가명ID로 대체 / 우편번호 뒤 2자리 부분 삭제 → '062**'
```

그리고 `code/02_k_anonymity.py`는 범주화만으로는 혼자 튀는 사람이 남는 문제를 **행 삭제**로 해결하는 과정을 보여 줍니다. (04-6에서 자세히)

```text
[범주화 후]          k=1, 혼자인 사람 1명  ↳ 재식별 위험: ('60대', '134', '의사')
[튀는 레코드 삭제 후] k=3, 혼자인 사람 0명
```

[[TIP("판단 기준: 지우기 전에 물어볼 것")]]

1. 이 항목이 **분석 목적에 꼭 필요한가?** → 아니면 삭제
2. 필요하다면 **덜 자세한 형태로도 충분한가?** → 범주화(04-2)
3. 몇몇 레코드만 튄다면 **그 레코드만** 처리할 수 있는가? → 로컬 삭제

[[/TIP]]

## 주의할 점

| 주의 | 설명 |
|---|---|
| 과도한 삭제 | 분석에 필요한 정보까지 지우면 결과의 가치가 사라짐 |
| 행 삭제의 편향 | 튀는 사람(예: 고령·희귀질환)만 지우면 분석 결과가 한쪽으로 치우칠 수 있음 → 삭제 비율과 영향을 기록 |
| 숨은 식별자 | 메모·비고 같은 자유 입력 칸에 이름·연락처가 섞여 있을 수 있음 → 04-7 텍스트 처리 |

## 실무 체크포인트

- [ ] 목적에 필요 없는 식별자를 모두 삭제했는가
- [ ] 자유 입력 칸(메모·비고)도 점검했는가
- [ ] 행 삭제를 했다면 삭제 비율과 분석에 미치는 영향을 기록했는가
